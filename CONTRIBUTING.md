# Contributing

Thanks for considering a contribution.

## Before opening a pull request

1. Search existing issues and pull requests to avoid duplicate work.
2. Open an issue first for substantial behavioral or architectural changes unless the repository documentation says otherwise.
3. Keep changes focused. Unrelated refactors should be submitted separately.
4. Add or update tests for behavior changes.
5. Run the repository's documented lint, test, build, and security checks locally when possible.
6. Do not include credentials, tokens, private keys, customer data, production data, or other secrets in commits, fixtures, logs, screenshots, or issue content.

## Pull requests

A pull request should explain:

- what changes;
- why the change is needed;
- how it was tested;
- any compatibility, migration, security, or operational impact.

Maintainers may request changes before merging. Approval can be dismissed automatically when new reviewable commits are pushed.

## Security issues

Do not open a public issue for a suspected vulnerability. Follow the repository's `SECURITY.md` policy instead.

## Licensing

By contributing, you agree that your contribution is provided under the license of the repository receiving the contribution.
